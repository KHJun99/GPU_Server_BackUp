## 이 트랙의 배경 (왜 reach-fix? 왜 multi-seed?)

### Phase 1 complete 직후의 ceiling
- 2026-05-21 L2 full PnP 학습 도달: 5조건 동시 success 55.6% (영상 검증 통과)
- `lift_history` 비율 65%가 next bottleneck — 큐브를 들어올리는 step부터 불안정
- L2 600k 추가 학습 시도했지만 plateau (47→50% SR, lift 64→57.7% dip) → reward만으로 안 깨짐

### Reach-fix 가설
- BC가 학습한 reach precision = oracle demo의 finger-cube 거리 분포의 상한
- 기존 oracle: approach exit 30mm, descend exit 15mm → BC reach 16mm가 descend tolerance와 정확히 일치
- 가설: oracle tolerance 줄이면 demo reach가 정밀해지고 → BC reach 정밀 → grasp 성공률 ↑ → lift_history ↑
- **변경**: `src/khj_rl/envs/cube_lift/oracle.py`
  - approach: `exit_distance_m=0.02, max_steps=80`
  - descend: `exit_distance_m=0.008, max_steps=90, min_steps=15`
- Pilot 결과 (4/5 success, descend 0.6mm 도달) 검증 후 1000 episode collect 진행

### Multi-seed 동시 학습 (옵션 A)
- 단일 seed로 50% → 65% delta가 나와도 그게 seed-noise인지 reach-fix signal인지 분리 불가
- GPU 0 + GPU 2 동시 학습으로 한 번에 noise band 측정. demo는 같은 1000개 공유 → collect 분기 불필요
- 사용자 합의: 2026-05-22 01:30 KST 자율 진행 권한 부여
